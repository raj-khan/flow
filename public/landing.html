# Web app architecture

A design sketched in isketch: 9 shapes and 8 connections. Build from it, and refer to shapes by their ids. To change the diagram, edit the source at the end and hand it back.

## Shapes

- **Browser** `browser`: where a flow starts or ends, or something outside the system. Single page app
- **CDN** `cdn`: a component or step. Static assets, cached at the edge
- **Load balancer** `lb`: a component or step. TLS termination
- **API** `api`: a component or step. REST, documented with OpenAPI
- **Job queue** `queue`: data going in or out. Emails, exports, webhooks
- **PostgreSQL** `db`: a data store. Primary data
- **Redis** `cache`: a data store. Sessions and cache
- **Worker** `worker`: a component or step. Runs queued jobs
- **Object storage** `files`: a file or document. Uploads and exports

## Connections

- **Browser** → **CDN**: assets
- **Browser** → **Load balancer**: HTTPS
- **Load balancer** → **API**
- **API** → **PostgreSQL**: SQL
- **API** → **Redis**
- **API** → **Job queue**: enqueue
- **Job queue** → **Worker**
- **Worker** → **Object storage**: write
